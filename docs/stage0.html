Just enough Python

You know C. Here is Python as a set of differences from C — seven complete programs, each one stepped through line by line.

python3 01_hello.py

Concept

You know C. Python is the same ideas with less typing. There is no compile step: python3 file.py runs the file top to bottom, and that is the whole build. There is no main(), no semicolons, no braces. A block is whatever is indented under a line that ends with a colon, so the indentation you already do for readability is now the syntax.

Variables have no declared type: x = 5 and later x = "five" are both fine. Strings are text in quotes, and an f-string puts a variable inside text: f"Namasthey {name}". That replaces every printf format you have ever written.

Three containers do all the work in this bootcamp. A list is [1, 2, 3]: an array that grows with .append. A tuple is ("Ravi", "Vizag"): a fixed group of values that you take apart with name, city = row. A dict is {"student_name": "Ravi"}: a struct whose fields are strings. Why these three? Because in Stage 2 SQLite hands you a list of tuples, and in Stage 5 you hand the browser a list of dicts. Everything between is a for loop with an if inside.

Two things will look strange. A line starting with @ above a function is a decorator; in this bootcamp it means exactly one thing, "register this function at this address", and nothing more. And None is Python's NULL: what you get back when a lookup finds nothing, guarded with if x is None:.

Nothing to write in this stage. Seven short programs follow, each complete. For each one, step through it with the Forward button or the arrow keys and watch the variables and the output appear on the right; then run the file yourself and see the same output. Everything not here — classes, try/except, list comprehensions, with, virtual environments — is deliberately left for later.

Takeaway

Quiz

rows = [("Ravi", "Vizag"), ("Divya", "Vijayawada")]. What is rows[1][0]?

rows[1] is the second tuple; [0] is its first item. Indexes start at 0, as in C.

d = {"name": "Ravi"}. Which line crashes?

d["city"] raises KeyError because there is no such key. d.get("city") returns None instead.

What does @route("/hai") above a function do?

A decorator here means one thing: register this function at that path. It runs later, when a request for /hai arrives.

In is_prime(4), why does d never reach 3?

return ends the function immediately, wherever it is. The loop does not finish; the function is already over.
