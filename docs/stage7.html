Stage 7

Someone else's client: the browser

A plain web page calls your backend. Two servers, two ports, and a server log that cannot tell curl from a browser.

python3 -m http.server 9000

Concept

Until now the only client was curl, and you were typing every request. The backend is finished when a program you did not write can use it. That program is a web page: a few dozen lines of HTML and JavaScript that you will run, click, and read — not edit. It is deliberately plain. It builds a URL, sends a GET, reads the JSON, and puts the rows in a table. curl with buttons.

Two programs need two ports. Your backend stays on 8080. The page is served by Python's built-in file server on 9000 — python3 -m http.server is a server too, one that only hands out files. The browser loads the page from 9000, and the page then talks to 8080. Two servers, two terminals, both logging.

Open app.js next to the page and read it. Above every fetch call is a comment with the curl command it replaces. fetch(url) sends the request; .then is what runs when the answer arrives. The page's own Request log prints, for each click, the method, the full URL, the status and how long it took — the four things curl -i shows you. One thing differs: the browser writes a space as %20 where you typed +. The server reads both.

Keep Terminal 1 in view. When the page asks for /students?college=…, the log line the server prints is the same line it printed for curl. The server cannot tell who is asking. That is the whole idea of a backend.

Takeaway

A backend is finished when a program you didn't write can use it. The frontend is curl with buttons.

Stuck?

Nothing to write. If the dropdown is empty and the banner is up: Terminal 1. If the browser says it cannot connect to localhost:9000: Terminal 2, and check you ran http.server inside code/frontend.

Quiz

Which program does the browser talk to when you click Fetch by college?

9000 only handed out index.html and app.js. Every click is a fetch to BACKEND, which is http://localhost:8080.

The server logs college=Sasi%20Junior%20College for the browser and college=Sasi+Junior+College for curl. What is different inside the route?

Both are encodings of a space. request.query.get decodes either. The route sees the same string.

What does .then(function (response) { ... }) mean in app.js?

fetch sends and returns immediately; the page keeps working. The function in .then runs later, when the response comes back.

The Request log shows method, URL, status, time. Where have you seen those before?

curl -i prints the status line and headers; the server log prints method, path and status. The page is showing the same request from the client's side.
