Stage 8

The inspector: curl -i with a mouse

The Network tab shows every field curl -i prints. Then break one header on purpose and watch the browser, not the server, say no.

response.headers["Access-Control-Allow-Origin"] = "*"

Concept

Every browser has curl -i built in. It is called the inspector, and its Network tab lists one row per request the page made. Click a row and you get two sub-tabs. Headers shows the Request URL, the Request Method, the Status Code, then the request headers and the response headers. Response shows the body. That is exactly the text curl -i prints, in the same order, with a mouse instead of a terminal.

The Console tab is where the browser prints errors the page did not handle — the same role as the traceback in Terminal 1, on the client side.

One thing lives only in the browser. A page loaded from port 9000 asks port 8080 for data. By default the browser will send that request and then refuse to hand the answer to the page, unless the answer carries a header saying the server allows it: Access-Control-Allow-Origin: *. That is the line in the Stage 5 hook you were told to ignore. The rule is called CORS. curl never checked it; the browser always does. You will remove the line, watch the server say 200 and the browser say no, and put it back.

Step through one request below, matching each curl -i line to the field the Network tab shows it in.

Task

Everything from Stage 7 stays running: the backend on 8080 in Terminal 1, the frontend on 9000 in Terminal 2, the page open in the browser.

  1. Browser. Press F12 (or Ctrl+Shift+I) to open the inspector. Click the Network tab. Now click Fetch by college on the page. One row appears: students?college=….

  2. Click that row. Under Headers: Request URL, Request Method GET, Status Code 200. Scroll down to Response Headers: content-type: application/json and access-control-allow-origin: *.

  3. Click the Response sub-tab. The JSON, exactly as curl printed it.

  4. Terminal 3 — curl. The same request with -i. Put the terminal beside the inspector and match line to field.

    terminal 3 — curl
    $ curl -i "localhost:8080/students?college=Sasi+Junior+College"HTTP/1.0 200 OKDate: Mon, 21 Sep 2026 09:37:39 GMTServer: WSGIServer/0.2 CPython/3.12.3Content-Type: application/jsonAccess-Control-Allow-Origin: *Content-Length: 351 {"count": 3, "students": [{"student_name": "Sruthi Sai Ravella", "inter_college": "Sasi Junior College", "inter_city": "Rajahmundry"}, {"student_name": "Sudheer Chandra Gupta", "inter_college": "Sasi Junior College", "inter_city": "Guntur"}, {"student_name": "Tejaswini Harini Achari", "inter_college": "Sasi Junior College", "inter_city": "Guntur"}]}

  5. Click Fetch by location and Search both. Two more rows in the Network tab. Open each and read its Request URL.

  6. Break it on purpose. In your editor, open code/stage5/server.py and put a # in front of all three lines of the hook — the @hook line, the def line, and the header line. Commenting only the last one leaves an empty function and Python refuses to start.

    server.py — the three lines, commented
    # @hook("after_request")# def allow_browser():#     response.headers["Access-Control-Allow-Origin"] = "*"   # This line matters in Stage 8. Ignore it for now.

    Terminal 1: Ctrl+C, start the server again with --db ../../data/all_students.db. Browser: click Fetch by college.

    The table does not change. The yellow banner appears. The Request log says FAILED (see the Console tab). In the Network tab the new row is red, with status (failed) or CORS error. Click the Console tab:

    browser — console tab
    Access to fetch at 'http://localhost:8080/students?college=Sasi%20Junior%20College' from origin 'http://localhost:9000' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.GET http://localhost:8080/students?college=Sasi%20Junior%20College net::ERR_FAILED 200 (OK)TypeError: Failed to fetch

    Read the second line again: net::ERR_FAILED 200 (OK). The server said 200. Now look at Terminal 1:

    terminal 1 — backend
    127.0.0.1 - - [21/Sep/2026 15:07:44] "GET /students?college=Sasi%20Junior%20College HTTP/1.1" 200 351

    The server answered, fully, as always. The browser received the answer and then refused to give it to the page, because the answer did not say the page was allowed to have it. Terminal 3: curl -i the same URL — it works, and the Access-Control-Allow-Origin line is simply gone from the headers.

  7. Fix it. Remove the three #s, Ctrl+C, start again, click again. The row is 200, the table fills, the banner goes.

    Terminal 1 through all of this: identical log lines, before, during and after. The break was never on the server's side.

Expected output

Three requests visible in the Network tab with Headers and Response matching curl -i field for field. During the break: a red row, the Console error above, a 200 in Terminal 1, and curl unaffected. After the fix: back to the Stage 7 state.

Takeaway

curl and the browser are the same client wearing different clothes. The Network tab is curl -i with a mouse; CORS is the one rule only the browser enforces.

Stuck?

If the server will not start after commenting: you commented one line, not three — IndentationError: expected an indented block is Python telling you the function has no body. If the page still fails after restoring: check Terminal 1 actually restarted (the start line prints again).

Quiz

With the hook commented out, Terminal 1 logs 200 351 but the table stays empty. Who refused?

The server did its job. The browser enforces CORS: a page from one origin may not read another origin's response unless that response allows it.

Where does curl -i's status line appear in the inspector?

Headers holds the request line, the status and both sets of headers; Response holds the body.

Why did curl -i keep working during the break?

CORS is a browser rule about pages. A terminal program has no origin to protect.

You comment out only the response.headers[...] line and restart. What happens?

A def with only a comment under it is a syntax error. Comment all three lines, or none.
