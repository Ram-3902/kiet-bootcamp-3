How Can I Use GitHub to Improve My Developer Profile?

First, Let Us Understand Why GitHub Profile Matters in India

Imagine two students applying for the same internship at a startup in Hyderabad.

Student A — Has a resume saying "I know HTML, CSS, JavaScript, and React."

Student B — Has the same resume, but also shares a GitHub link where the recruiter can see 8 real deployed projects, clean code, regular commits, and a well-written profile.

Who gets the interview call?

Student B. Every single time.

In India's tech industry today — especially in startups, product companies, and any company that takes engineering seriously — your GitHub profile is your second resume.

Sometimes it matters more than your actual resume.

Recruiters at companies like Razorpay, Zepto, CRED, Groww, and even big MNCs like Google and Microsoft India actively look at GitHub profiles before calling candidates.

A strong GitHub profile says — "This person actually builds things. They are not just claiming skills. Here is the proof."

This document tells you exactly how to build that profile — from zero, as a student, step by step.

What Does a Strong GitHub Profile Look Like?

Before building it — let us understand what recruiters and senior developers actually look at when they visit your GitHub profile.

They look at:

  1. Your profile picture, name, bio, and links
  2. Your pinned repositories — the 6 projects you chose to highlight
  3. Your contribution graph — the green squares showing your activity
  4. Your README on individual repositories
  5. The quality of your commit messages and code
  6. Whether your projects are actually deployed and live

Let us fix each one of these — properly.

Part 1 — Set Up Your Profile Properly

Your GitHub profile page is like your visiting card. It should be clean, complete, and professional.

Step 1 — Use a Real Profile Picture

Do not use the default GitHub avatar (the robot-looking thing).

Use a real photo of yourself — or at minimum, a clean avatar or illustration that represents you.

Profiles with a real photo get taken more seriously. It shows you are a real person who is proud of their work.

Step 2 — Set Your Name Properly

Set your display name (not just username) to your real full name.

Go to Settings → Profile → Name → Type your full name.

Step 3 — Write a Strong Bio

Your bio appears right under your name. You get 160 characters.

Make it count. Tell people:

  • What you are (student, developer, learner)
  • What you build or are learning
  • What you are looking for

Examples of weak bios:

text
"Student""I like coding""Learning web development"

Step 4 — Add Your Location

Add your city and state — example: "Visakhapatnam, Andhra Pradesh"

Recruiters hiring for local or remote roles in India often filter by location. Being visible here helps.

Step 5 — Add Your Links

GitHub gives you space for:

  • Website — Put the link to your portfolio website here
  • Twitter/X — If you post about tech, add it
  • LinkedIn — Add your LinkedIn profile link

At minimum — your portfolio website link should always be here.

Step 6 — Add Your Pronouns and Organisation

If you are a student — add your college name in the Organisation field.

Example: @GITAM University or @JNTUK

This immediately tells anyone visiting your profile that you are a student — and sets the right expectations.

Part 2 — Create a GitHub Profile README

This is the most powerful thing you can do for your GitHub profile and most students do not even know it exists.

A GitHub Profile README is a special README file that appears directly on your GitHub profile page — like a personalised introduction banner at the top of your profile.

What to Put in Your Profile README

Here is a template you can use and customise:

README.md
# Hi there, I am Rahul Kumar 👋 ## About Me- 🎓 B.Tech Computer Science student at GITAM University, Visakhapatnam- 🌱 Currently learning React and Node.js- 💻 I love building web apps that solve real problems- 🔭 Working on: My portfolio website and a Weather App- 📫 Reach me at: rahul@email.com- 🌐 Portfolio: [rahulkumar.dev](https://rahulkumar.dev) ## Technologies I Work With **Frontend:**HTML | CSS | JavaScript | React **Tools:**Git | GitHub | VS Code | WSL Ubuntu **Learning Next:**Node.js | Express | MongoDB ## My Projects | Project | Description | Live Demo ||---|---|---|| Portfolio Website | Personal portfolio built with HTML and CSS | [View Live](https://link) || Weather App | Shows real weather data using OpenWeatherMap API | [View Live](https://link) || Quiz App | Multiple choice quiz with score tracking | [View Live](https://link) |

Part 3 — Pin Your Best Projects

GitHub lets you pin up to 6 repositories that appear at the top of your profile.

This is the first thing people see after your profile README. These 6 pinned repos are your showcase — choose them very carefully.

How to Pin Repositories

Step 1 — Go to your GitHub profile page

Step 2 — Click "Customize your pins" (appears below your profile README)

Step 3 — Select the 6 repositories you want to pin

Step 4 — Click Save

Part 4 — The Contribution Graph — The Green Squares

You have seen those green squares on GitHub profiles — a calendar where some days are darker green than others.

This is your contribution graph — it shows every day you pushed code, opened a pull request, created an issue, or reviewed code on GitHub.

The darker the green — the more contributions that day.

A profile with lots of green squares says — "This person codes regularly. They are consistent. They are serious about development."

A profile with mostly grey squares (no contributions) says the opposite.

How to Keep Your Contribution Graph Active

Habit 1 — Code Every Day — Even a Little

You do not need to build a new feature every day. Even small contributions count:

  • Fix a typo in your README
  • Add a comment to explain a function
  • Update your portfolio with a new project
  • Improve CSS on an existing project
  • Refactor one messy function

The goal is consistency — not volume. A little bit every day beats a lot once a week.

Habit 2 — Commit to Public Repositories

Private repositories do NOT show on your contribution graph (unless you enable that option in settings).

Make sure your projects are in public repositories so your contributions count and are visible to everyone.

Habit 3 — Work on Real Projects, Not Just Tutorials

Tutorial code that you never push to GitHub does not count. Work on your own projects — push them to GitHub — and every commit shows up on your graph.

Part 5 — Write Good Commit Messages

Your commit messages are visible to everyone who visits your repository. They show your professionalism and how you think about your work.

Bad Commit Messages (What Most Beginners Do)

text
git commit -m "changes"git commit -m "fix"git commit -m "updated stuff"git commit -m "asdfghjkl"git commit -m "final"git commit -m "FINAL FINAL"git commit -m "please work"

These messages are useless. They tell nobody — including your future self — what actually changed.

Good Commit Messages (What Professionals Do)

text
git commit -m "added responsive navbar with hamburger menu for mobile"git commit -m "fixed weather API returning undefined for invalid city names"git commit -m "refactored quiz logic to use array of objects instead of parallel arrays"git commit -m "added dark mode toggle with localStorage persistence"git commit -m "updated README with live demo link and screenshot"

Part 6 — Contribute to Open Source

Contributing to open source projects is one of the fastest ways to level up your GitHub profile and your skills at the same time.

When you contribute to someone else's real project — it shows that:

  • You can read and understand code written by others
  • You can work in a real collaborative environment
  • You care about the developer community

Part 7 — Things That Actually Hurt Your GitHub Profile

Just as some things help — some things actively make your profile look worse. Avoid these:

Empty Repositories With No Files

A repository that just has a name and one blank file looks worse than not having it at all. Either build the project or do not create the repository.

Repositories That Are Just Tutorial Clones

"Cloned Brad Traversy's JavaScript course" is not a project. It is a copy.

If you followed a tutorial — make changes. Add a feature. Change the design. Make it different enough that it is YOUR project.

No README on Any Repository

Every single repository you make public should have a README. No exceptions. A repository with no README looks abandoned and unprofessional.

Private Everything

If all your repositories are private — your profile looks completely empty. Recruiters see nothing. Make your actual projects public.

Committing Everything at the End

If your project has only 1 or 2 commits — it shows you are not using Git properly. Commit small and often. 20 commits on a project looks much better than 1 giant commit.

Inconsistent or Inactive Profile

A profile that had lots of activity 6 months ago and nothing since — is less impressive than a profile with steady, regular activity.

Consistency beats intensity. A few commits every week is better than 100 commits in one day and then nothing for months.

Summary — Everything in One Paragraph

Your GitHub profile is your second resume — and in India's current tech hiring landscape, it often matters more than the first one. Set up your profile completely with a real photo, your full name, a strong bio, and links to your portfolio and LinkedIn. Create a GitHub Profile README in a special repository that matches your username — it appears as a banner on your profile and can include stats, project tables, and technology badges. Pin your 6 best projects with complete READMEs, screenshots, and live demo links. Keep your contribution graph active by committing regularly — even small changes count. Write clear, specific commit messages that show professionalism. Make your real projects public so your work is visible. Make at least one open source contribution — start with fixing a typo if needed. Push college projects and assignments to GitHub too. Build this profile consistently over 6 months and by the time you apply for internships or jobs, you will have a profile that proves — without any doubt — that you are a developer who actually builds things.
