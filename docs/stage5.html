Stage 5 · Session 2 · afternoon

Join the two halves

Request in, SQL in the middle, JSON out — one function, repeated four times with different SQL.

rows = query("... WHERE inter_college = ?", [college])

Concept

Everything so far was one half. Stage 2 read rows out of a file and printed them. Stage 4 took a request and returned a dict. This stage joins them, and the join is one function long. Read the given route /students line by line before you write anything, because the four routes you add are the same function with different SQL.

Unpack. request.query.get("college") pulls the value after ?college=. If it is None, the client forgot it: set the status to 400 and return an error dict. That is the whole of input checking today.

Query. query(sql, params) is a helper written for you — the only function in this stage you do not write. It opens the connection, makes the cursor, runs execute with your ? values, does fetchall, closes, and hands back the list of tuples. Stage 2, folded into five lines you can reuse.

Pack. pack(rows) turns the list of tuples into a list of dicts with the three column names as keys. Stage 0 block 7, with the loop already written. Then you return a dict around it: {"count": len(rows), "students": pack(rows)}. Bottle makes it JSON. Step through one request to watch the dict grow.

One more line sits in the file: a hook that adds a header to every response. The comment says to ignore it, and today that is right. Stage 8 is about that line.

Quiz

/students/search?college=Narayana+Junior+College with no location. Which line answers?

Unpack found location missing. The guard returns the error dict before any SQL runs.

query("SELECT COUNT(*) FROM students WHERE inter_college = ?", [college]) returns what?

query() always returns what fetchall() returns: a list of tuples. COUNT gives one row with one column, so rows[0][0] is the number.

Why does curl "localhost:8080/students?college=Narayana Junior College" fail before reaching the server?

curl stops with a malformed-URL error. Spaces must be written as + (or %20). The server decodes them back to spaces.

What does {"count": 0, "students": []} mean?

A correct question with an empty answer. Missing parameters give 400; missing files give a traceback; this is a clean 200.
