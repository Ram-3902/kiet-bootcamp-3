Stage 2

Python talks to the database

Module, connection, cursor. execute positions, fetchall reads, and the value goes in through a question mark.

cursor.execute("SELECT student_name FROM students WHERE inter_college = ?", [college])

Concept

The sqlite3 shell in Stage 1 typed SQL and printed rows. A program can do the same: send SQL, get rows back, and then do whatever it wants with them. Three objects make that happen, and each has a C counterpart you already know.

The sqlite3 module is the driver — import sqlite3 is your #include <stdio.h>. The connection is the open file, your FILE *: sqlite3.connect("team_details.db") opens it, connection.close() closes it. The cursor is where you run a query and read what comes back — think of it as the position in the file.

Two calls, and the difference between them matters. cursor.execute(sql) positions: it runs the query but hands you nothing. cursor.fetchall() reads: it gives you every row as a list of tuples — the exact shape from Stage 0, block 2. One tuple per row, one item per column, in the order you named the columns.

One rule, starting today and for the rest of your life: never paste a value into the SQL string. Write ? where the value goes and pass the value separately, in a list. The same query then serves any college, and text with a quote in it cannot break or hijack your SQL. Step through read_all.py to watch the three objects appear.

Expected output

The query you need has one ? and one value in the list after it:

the shape
cursor.execute("SELECT student_name FROM students WHERE inter_college = ?", [college])rows = cursor.fetchall()for row in rows:    print(row[0])

Each row is a tuple with one item, so row[0] is the name. The quotes around the college name on the command line matter: without them the shell splits it into three arguments and sys.argv[1] is just Narayana.

Quiz

After cursor.execute("SELECT * FROM students"), where are the rows?

execute positions, fetch reads. The call returns nothing you need; the rows come from cursor.fetchall().

rows = cursor.fetchall() gave [('Ravi Teja Kanchi',), ('Sai Kiran Bommu',)]. What is rows[1][0]?

rows[1] is the second tuple; [0] is its only item. A one-column SELECT still gives tuples, just with one item each.

Why WHERE inter_college = ? with [college], instead of building the string with the name inside?

With ?, a name containing a quote is just a name. Pasted into the string it would end the SQL early — the classic injection bug.

python3 by_college.py Narayana Junior College (no quotes) prints nothing. Why?

The shell split the name into three arguments. The query looked for a college called exactly 'Narayana' and found none.
