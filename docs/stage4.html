Stage 4 · Session 2 · afternoon

Write your own server

Two functions, two addresses, port 8081. Return a string for text, a dict for JSON.

@route("/wish/<name>")

Concept

A route is a function with an address. In Stage 3 you saw four addresses answer; today you give two functions addresses of your own. The line @route("/hai") above def hai(): says one thing: when this path is asked for, call this function. It does not call it now. It does not change what the function does. It writes the address into Bottle's list, and run() at the bottom starts the waiting loop that consults that list.

What the function returns becomes the answer. Return a string and the client gets text. Return a dict and Bottle turns it into JSON and sets Content-Type: application/json for you — the json.dumps from Stage 0 block 3, done automatically. You never build the response by hand.

The doors from Stage 3 map to pieces of Bottle. A path parameter, <name> in the route, becomes a function argument — def wish(name): receives whatever was in the URL. The query string is request.query.get("k"); that is for Stage 5. Today one route takes a name from the path and the other takes nothing at all.

Your server listens on port 8081, so it can run at the same time as the Stage 3 server on 8080. Two programs, two ports, one machine; curl picks which one by the number after the colon. Keep both running for the last step and watch two terminals answer.

Quiz

You change the text in wish(), save, and curl still shows the old text. Why?

The running process has the old code in memory. Ctrl+C and python3 server.py again loads the new file.

A route returns {"inter_city": "Visakhapatnam", "ok": True}. What does curl print?

Bottle runs json.dumps on the dict: double quotes, lowercase true. That is JSON, not Python.

curl -i localhost:8081/about shows Content-Type: application/json; curl -i localhost:8081/wish/Ravi shows text/html. Why?

Bottle sets Content-Type from what the function returns: a dict becomes JSON, a string is sent as text.

Both servers are running. curl localhost:8080/wish/Ravi gives a 404. Why?

The port picks the program. The Stage 3 program on 8080 has /hai, /hello, /isprime and /greet — /wish exists only in yours on 8081.
