sqlite3 command line

Open a .db file, look inside, run a .sql script.

sqlite3 team_details.db

Open a database

terminal
$ cd ~/kiet-bootcamp-3/data$ sqlite3 team_details.dbSQLite version 3.45.1 2024-01-30 16:01:20Enter ".help" for usage hints.sqlite>

The file is created if it does not exist. The prompt changes to sqlite>: you are now typing SQL, not shell. Every SQL statement ends with ;. Dot-commands do not.

No sqlite3 command? Python ships the same shell:

terminal
$ python3 -m sqlite3 team_details.dbsqlite>

Dot-commands

Lines starting with a dot are settings of the shell, not SQL. No semicolon. The Python fallback shell has none of them and prints rows as tuples.

sqlite> with .mode box
sqlite> .mode boxsqlite> SELECT student_name, inter_city FROM students WHERE inter_city = 'Vijayawada';┌────────────────────────┬────────────┐│      student_name      │ inter_city │├────────────────────────┼────────────┤│ Lakshmi Prasanna Gudla │ Vijayawada ││ Divya Sree Pothula     │ Vijayawada │└────────────────────────┴────────────┘
.tables
list the tables in this file
.schema
print the CREATE TABLE statements
.mode box
draw every result as a table with borders and the column names on top — set this first
.headers on
print column names above results (box mode already does)
.mode column
align results in plain columns, no borders (the default is a|b|c)
.read schema.sql
run every statement in a file
.quit
leave (or Ctrl+D)

Run a .sql file

terminal
$ sqlite3 all_students.db < all_students.sql$ sqlite3 all_students.db "SELECT COUNT(*) FROM students;"200

< feeds the file to sqlite3 as if you typed it. The second form runs one statement and exits — handy for a quick count.

With the Python fallback, use .read from inside the shell:

terminal
$ python3 -m sqlite3 all_students.dbsqlite> .read all_students.sqlsqlite> SELECT COUNT(*) FROM students;200sqlite> .quit
