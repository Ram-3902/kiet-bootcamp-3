HTTP basics

The request line, the status line, and the three doors.

GET /greet?name=Ravi HTTP/1.1

A request

what curl sends
GET /greet?name=Ravi&lang=en HTTP/1.1Host: localhost:8080Accept: */*

First line: method, path with its query string, protocol version. Then headers, one per line. Then a blank line. Then the body, if any (a GET has none).

what curl sends for a POST
POST /isprime HTTP/1.1Host: localhost:8080Content-Type: application/jsonContent-Length: 14 {"number": 17}

A response

what the server sends back
HTTP/1.0 200 OKContent-Type: application/jsonContent-Length: 32 {"number": 17, "is_prime": true}

First line: protocol, status code, reason. Then headers. Blank line. Body. curl -i shows exactly this; the browser's Network tab shows the same fields under Headers and Response.

Three places data can be

path
/hello/Ravi — part of the address. Bottle: @route("/hello/<name>")
query string
/greet?name=Ravi&lang=en — after the ?. Bottle: request.query.get("name")
body
-d '{"number": 17}' — only with POST. Bottle: request.json

Status codes you will see

200
OK. The route ran and returned something.
400
Bad request. The route ran and decided your request was missing or wrong. The body says what.
404
Not found. No route has that path.
500
The route crashed. With debug=True the traceback is in Terminal 1.

Content-Type

A header that says what the body is. text/html when a route returns a string, application/json when it returns a dict. When you POST JSON you must send it too, or the server will not parse the body.
